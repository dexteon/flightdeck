# Flightdeck

A cross-board fleet command center for the [Hermes Agent](https://github.com/NousResearch/hermes-agent)
kanban.

Hermes ships a good single-board task editor at `127.0.0.1:9119/kanban`. It cannot show
you the fleet: 14 board databases holding 1279 tasks, switched one at a time. And several
things its backend already does have no UI at all, including live per-worker process
inspection.

Flightdeck owns what Hermes structurally cannot do, and delegates ordinary card create
and edit back to Hermes by deep link.

- Fleet view across every board at once
- Live worker inspector: active workers, per-process cpu and memory, heartbeat staleness,
  streaming log follow, terminate
- Cross-board unified queue, global search, triage and blocked inbox
- Dependency graph over `task_links`

## How it talks to Hermes

**Reads go straight to SQLite, read-only.** Hermes coordinates its workers with WAL plus
`BEGIN IMMEDIATE` plus compare-and-swap on `tasks.status`/`claim_lock`. Under WAL, readers
neither block nor are blocked by the writer, so direct reads are safe. They also let us
query all 14 databases at once, which the REST API cannot do, and they keep working when
the Hermes dashboard is not running.

**Writes go through the Hermes REST API.** Reimplementing the claim protocol would risk
corrupting dispatcher state and break on every upstream schema bump, so Hermes stays the
owner of task lifecycle.

**When Hermes is down, Flightdeck goes read-only rather than blank.** That is structural,
not careful: nothing on the read path touches Hermes.

Validated against Hermes commit `69e857425c`. See [`docs/hermes-api-notes.md`](docs/hermes-api-notes.md)
and [`docs/transition-matrix.md`](docs/transition-matrix.md), both generated by the spike
scripts and worth regenerating after a Hermes upgrade.

## Running it

```powershell
uv venv --python 3.12
uv pip install -e ".[dev]"
.\scripts\start.ps1          # http://127.0.0.1:9310
.\scripts\status.ps1
.\scripts\stop.ps1
```

`start.ps1` records the PID at spawn; `stop.ps1` kills only that PID after confirming the
process image and start time match. It never matches on a command line.

## Development against fixtures

```powershell
.\scripts\dev.ps1 -Fixtures
```

Points `HERMES_KANBAN_HOME` at a copied fixture tree, so the whole UI is exercisable with
no possibility of touching live data. This is the default mode for development.

Write-path tests are opt-in and refuse to run anywhere but a scratch board:

```powershell
$env:FLIGHTDECK_WRITE_TEST_BOARD = 'flightdeck-test'
.venv\Scripts\python.exe -m pytest tests/write
```
